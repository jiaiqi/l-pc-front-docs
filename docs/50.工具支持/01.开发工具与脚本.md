# 开发工具与脚本

> **l-pc-front 项目开发工具、脚本与环境配置完整指南**

本文档汇总了项目中使用的所有开发工具、自动化脚本和 CLI 工具，帮助开发者快速了解和使用项目提供的各类工具，提升开发效率。

## 工具概览

项目提供以下类别的工具支持：

| 工具类别 | 工具名称 | 说明 |
|----------|----------|------|
| 版本管理 | Git Tag 管理工具 | 交互式 Git 标签创建与管理 |
| 代码提交 | Git 提交规范工具 | AngularJS 规范提交信息 |
| 版本文件 | 版本文件生成工具 | 自动生成 version.json |
| 构建部署 | 项目构建脚本 | 构建与部署相关脚本 |

## 核心开发环境

| 工具名称 | 版本要求 | 用途说明 |
|----------|----------|----------|

| Git | >= 2.0 | 版本控制工具 |

|----------|----------|
| VS Code | 代码编辑器，推荐安装项目推荐插件 |
| Vue DevTools | Vue 应用调试工具 |

| Notepad++ | Windows 环境下文本编辑（脚本工具支持） |

## 工具脚本详解

### 1. Git Tag 管理工具

**脚本路径**: `scripts/git-tag-cli.js`

**功能**: 交互式 Git 标签创建与管理工具，简化版本发布流程

**核心功能**:
- 自动检测当前分支
- 检查未提交的更改
- 智能生成下一个版本号建议
- 自动获取提交记录作为标签描述
- 支持在编辑器中编辑标签描述
- 一键创建并推送标签到远程
- 可选生成版本文件
- 可选构建项目

**使用方法**:

```bash
# 使用 npm 脚本
npm run git-tag

# 或直接运行
node scripts/git-tag-cli.js
```

**使用场景**:
- 发布新版本时创建 Git 标签
- 版本管理与追溯
- 自动化版本发布流程

[查看详细文档](/tools/git-tag)

---

### 2. Git 提交规范工具

**脚本路径**: `scripts/git-commit-cli.js`

**功能**: 基于 AngularJS 规范的交互式 Git 提交工具

**核心功能**:
- 自动检测变更文件
- 提供 11 种标准提交类型选择
- 支持输入影响范围
- 支持简短描述和详细描述
- 集成多种编辑器编辑详细描述
- 支持标记破坏性变更
- 支持关联 Issue
- 提交信息预览与确认

**提交类型**:

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| feat | 新功能 | 新增功能模块 |
| fix | 修复 Bug | 修复问题 |
| docs | 文档 | 更新文档 |
| style | 格式 | 代码格式化 |
| refactor | 重构 | 代码重构 |
| perf | 性能优化 | 优化性能 |
| test | 测试 | 添加测试 |
| chore | 构建/工具 | 构建工具变动 |
| revert | 回滚 | 回滚提交 |
| build | 构建系统 | 构建配置变动 |
| ci | CI 配置 | 持续集成配置 |

**使用方法**:

```bash
node scripts/git-commit-cli.js
```

**使用场景**:
- 规范代码提交信息
- 团队协作开发
- 自动生成 CHANGELOG

[查看详细文档](/tools/git-commit-cli)

---

### 3. 版本文件生成工具

**脚本路径**: `scripts/generate-version.js`

**功能**: 自动生成包含版本信息的 `version.json` 文件

**核心功能**:
- 从 Git 获取版本号（Tag）
- 获取 Commit Hash 作为构建号
- 获取提交时间和构建时间
- 支持三种描述生成方式：
  - 自上次 Tag 以来的提交日志
  - 最近 N 次提交日志
  - 手动输入
- 支持在编辑器中编辑描述
- 生成 `public/version.json` 文件

**生成文件格式**:

```json
{
  "version": "v1.2.3",
  "build": "abc1234",
  "commitTime": "2025-01-30 10:00:00 +0800",
  "buildTime": "2025-01-30 14:30:00",
  "tagDescription": "..."
}
```

**使用方法**:

```bash
# 使用 npm 脚本
npm run generate-version

# 或直接运行
node scripts/generate-version.js
```

**使用场景**:
- 版本发布时生成版本信息
- 前端更新检查
- CI/CD 流程集成

[查看详细文档](/tools/generate-version)

## 工具使用流程

### 版本发布完整流程

```
1. 完成功能开发
   └── 编写代码、测试

2. 提交代码
   └── 运行 git-commit-cli.js
   └── 选择提交类型、填写描述
   └── 完成提交

3. 创建版本标签
   └── 运行 git-tag-cli.js
   └── 确认版本号、编辑标签描述
   └── 创建并推送标签

4. 生成版本文件
   └── 运行 generate-version.js
   └── 选择描述生成方式
   └── 生成 version.json

5. 构建项目
   └── npm run build

6. 部署上线
```

### 日常开发流程

```
1. 修改代码

2. 提交代码（使用提交规范工具）
   └── node scripts/git-commit-cli.js

3. 推送代码
   └── git push
```

## 最佳实践

### 1. 工具使用建议

- **Git 提交规范工具**：每次提交代码时使用，保持提交信息规范
- **Git Tag 管理工具**：发布新版本时使用，确保版本管理规范
- **版本文件生成工具**：与 Git Tag 工具配合使用，在创建标签后生成版本文件

### 2. 版本号管理

- 遵循语义化版本规范（SemVer）
- 版本号格式：`v主版本号.次版本号.修订版本号`
- 示例：`v1.2.3`、`v2.0.0-beta.1`

### 3. 提交信息规范

- 使用 AngularJS 提交规范
- 格式：`<类型>(<范围>): <描述>`
- 示例：`feat(user): 添加用户登录功能`

### 4. 编辑器配置

工具支持以下编辑器：

**Windows**:
- Notepad++（推荐）
- VSCode
- 记事本

**Linux/Mac**:
- Nano
- Vim
- VSCode

建议安装 Notepad++ 或 VSCode 以获得最佳体验。

## 常见问题

### Q: 脚本运行失败怎么办？

A: 检查以下几点：
1. Node.js 版本是否符合要求（>= 18.20.8）
2. 是否在项目根目录运行
3. Git 仓库是否正常初始化
4. 是否有文件权限问题

### Q: 如何查看脚本帮助？

A: 脚本运行时会显示交互式引导，按照提示操作即可。详细文档请参考各工具的独立文档页面。

### Q: 可以修改脚本功能吗？

A: 可以，脚本位于 `scripts/` 目录下，使用 Node.js 编写，可以根据需求进行修改。

### Q: 工具支持哪些操作系统？

A: 所有工具都支持 Windows、macOS 和 Linux 系统。
