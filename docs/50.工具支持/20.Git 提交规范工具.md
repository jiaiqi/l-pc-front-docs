# Git 提交规范工具

> **基于 AngularJS 规范的交互式 Git 提交工具，规范代码提交信息**

本文档介绍项目中使用的 Git 提交规范工具，帮助开发者按照 AngularJS 提交规范创建规范的提交信息，提高代码版本管理的可读性和可追溯性。

## 功能特性

- **交互式命令行界面**：友好的交互体验，引导式操作流程
- **AngularJS 规范支持**：内置 11 种标准提交类型
- **变更文件检测**：自动检测并显示待提交的变更文件
- **编辑器集成**：支持多种编辑器编辑详细描述
- **智能编辑器检测**：自动检测系统中可用的编辑器
- **提交信息预览**：提交前预览完整的提交信息
- **破坏性变更标记**：支持标记不兼容的 API 变更
- **Issue 关联**：支持关联相关的 Issue 编号
- **多平台支持**：兼容 Windows、macOS、Linux 系统

## 前置条件

在使用本工具前，请确保已安装以下依赖：

- **Node.js** >= 18.20.8
- **Git** >= 2.0

## 使用方法

### 启动工具

在项目根目录下运行以下命令启动工具：

```bash
node scripts/git-commit-cli.js
```

### 操作流程

#### 1. 变更文件检测

工具启动后会自动检测变更的文件并显示：

```
═══ 🚀 AngularJS 规范 Git 提交工具 ═══
ℹ 检测到 3 个变更文件：
  [M] src/components/UserList.vue
  [A] src/api/user.js
  [M] src/store/modules/user.js
────────────────────────────────────────
```

**文件状态说明：**

| 状态 | 含义 | 颜色 |
|------|------|------|
| M | 修改（Modified） | 黄色 |
| A | 新增（Added） | 绿色 |
| D | 删除（Deleted） | 红色 |

#### 2. 选择提交类型

选择符合本次提交的 AngularJS 规范类型：

```
═══ 请选择提交类型 ═══
  1. ✨ feat - 新功能（feature）
  2. 🐛 fix - 修补 bug
  3. 📚 docs - 文档（documentation）
  4. 💎 style - 格式（不影响代码运行的变动）
  5. ♻️ refactor - 重构（即不是新增功能，也不是修改 bug 的代码变动）
  6. 🚀 perf - 性能优化
  7. ✅ test - 增加测试
  8. 🔧 chore - 构建过程或辅助工具的变动
  9. ⏪ revert - 回滚到上一个版本
  10. 📦 build - 构建系统或外部依赖的变动
  11. 🔨 ci - CI 配置或脚本的变动

请输入选项编号 (默认: 1)
```

**提交类型详解：**

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| feat | 新功能 | 新增用户登录功能 |
| fix | 修复 Bug | 修复表格排序问题 |
| docs | 文档 | 更新 API 文档 |
| style | 格式 | 代码格式化、分号补全 |
| refactor | 重构 | 重构用户模块代码 |
| perf | 性能优化 | 优化列表渲染性能 |
| test | 测试 | 添加单元测试 |
| chore | 构建/工具 | 更新构建配置 |
| revert | 回滚 | 回滚到上一版本 |
| build | 构建系统 | 更新 webpack 配置 |
| ci | CI 配置 | 更新 GitHub Actions |

#### 3. 输入影响范围（可选）

输入本次提交影响的代码范围：

```
═══ 请输入影响范围（可选） ═══
例如: src/components/common, 或按回车跳过
影响范围
```

**示例：**
- `src/components/UserList`
- `src/api`
- `docs`

#### 4. 输入简短描述

输入本次提交的简短描述（必填）：

```
═══ 请输入简短描述 ═══
一句话描述本次提交的主要内容
简短描述 (必填)
```

**描述规范：**
- 使用简洁明了的语言
- 首字母小写
- 不以句号结尾
- 控制在 50 个字符以内

**正确示例：**
- `添加用户列表分页功能`
- `修复登录页面样式问题`
- `更新项目文档`

**错误示例：**
- `添加了用户列表分页功能。`（以句号结尾）
- `Fix`（过于简短）
- `修复了一些问题`（过于笼统）

#### 5. 添加详细描述（可选）

如果需要添加详细描述，选择使用编辑器编辑：

```
═══ 详细描述 ═══
是否需要添加详细描述? (y/N)
```

选择 `y` 后，工具会：
1. 生成默认的详细描述模板
2. 打开系统默认编辑器
3. 允许编辑多行内容
4. 保存后自动读取

**支持的编辑器：**

| 平台 | 编辑器 | 优先级 |
|------|--------|--------|
| Windows | Notepad++ | 1 |
| Windows | VSCode | 2 |
| Windows | 记事本 | 3（保底） |
| Linux/Mac | Nano | 1 |
| Linux/Mac | Vim | 2 |
| Linux/Mac | VSCode | 3 |

#### 6. 标记破坏性变更（可选）

如果本次提交包含破坏性变更，需要进行标记：

```
是否有破坏性变更? (y/N)
```

选择 `y` 后输入变更说明：

```
请输入破坏性变更说明
```

**破坏性变更示例：**
- `移除用户登录 API 的旧版本接口`
- `修改数据库表结构，需要重新迁移`
- `更新配置文件格式，不兼容旧版本`

#### 7. 关联 Issue（可选）

如果本次提交关联了 Issue，可以添加引用：

```
是否有关联的 issue? (y/N)
```

选择 `y` 后输入 Issue 引用：

```
请输入 issue 引用 (例如: #123, fixes #456)
```

**Issue 引用格式：**
- `#123` - 关联 Issue #123
- `fixes #456` - 修复 Issue #456（会自动关闭）
- `closes #789` - 关闭 Issue #789
- `refs #100, #101` - 关联多个 Issue

#### 8. 提交信息预览

提交前预览完整的提交信息：

```
═══ 提交信息预览 ═══
────────────────────────────────────────
feat(src/components): 添加用户列表分页功能

实现用户列表的分页加载功能，支持页码跳转和每页数量设置。

BREAKING CHANGE: 移除旧的列表加载接口
closes #123
────────────────────────────────────────
```

#### 9. 确认提交

确认后执行提交：

```
是否确认提交? (y/N)
ℹ 正在执行 git commit...
✓ 提交成功！
ℹ 最新提交: abc1234 feat(src/components): 添加用户列表分页功能
```

## 提交信息格式

### 完整格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 格式说明

| 部分 | 必填 | 说明 |
|------|------|------|
| type | 是 | 提交类型（feat、fix 等） |
| scope | 否 | 影响范围 |
| subject | 是 | 简短描述 |
| body | 否 | 详细描述 |
| footer | 否 | 破坏性变更、Issue 引用 |

### 示例

**简单提交：**

```
fix: 修复登录按钮点击无效问题
```

**带范围的提交：**

```
feat(user): 添加用户资料编辑功能
```

**带详细描述的提交：**

```
feat(api): 添加用户认证接口

实现基于 JWT 的用户认证接口，包括：
- 用户登录接口
- Token 刷新接口
- 用户登出接口

接口文档已更新至 /docs/api/auth.md
```

**带破坏性变更的提交：**

```
feat(api): 重构用户认证接口

重构用户认证流程，提升安全性。

BREAKING CHANGE: 移除旧的 /api/login 接口，
请使用新的 /api/v2/auth/login 接口
```

**关联 Issue 的提交：**

```
fix(ui): 修复表格排序异常

修复点击表头排序时数据不更新的问题。

fixes #456
```

## 最佳实践

### 1. 提交频率

- **频繁提交**：小步快跑，每次提交只包含一个逻辑变更
- **原子性提交**：每个提交应该是独立的、完整的
- **避免大提交**：将大功能拆分为多个小提交

### 2. 提交信息编写

**好的提交信息：**

```
feat(auth): 添加 OAuth2 登录支持

集成 GitHub 和 Gitee OAuth2 登录，支持：
- 第三方账号绑定
- 自动用户信息同步
- 登录状态持久化

closes #234
```

**不好的提交信息：**

```
update code
修改了一些东西
fix bug
```

### 3. 提交类型选择

- **feat**：新增功能时使用
- **fix**：修复 Bug 时使用
- **docs**：仅修改文档时使用
- **style**：不影响代码逻辑的格式修改
- **refactor**：代码重构，不新增功能也不修复 Bug
- **perf**：性能优化相关
- **test**：测试相关
- **chore**：构建工具、依赖更新等

### 4. 范围命名

- 使用文件路径或模块名
- 多个范围用逗号分隔
- 保持简洁，避免过长

**示例：**
- `src/components`
- `api,utils`
- `docs`

## 常见问题

### Q: 如何修改已提交的提交信息？

A: 使用 `git commit --amend` 修改最近一次提交：

```bash
# 修改最近一次提交
git commit --amend

# 强制推送到远程（谨慎使用）
git push --force-with-lease
```

### Q: 提交后发现漏了文件怎么办？

A: 追加文件到最近一次提交：

```bash
# 添加遗漏的文件
git add 遗漏的文件

# 追加到最近一次提交
git commit --amend --no-edit
```

### Q: 如何批量修改历史提交？

A: 使用交互式 rebase：

```bash
# 修改最近 3 次提交
git rebase -i HEAD~3
```

### Q: 提交规范有什么好处？

A: 规范的提交信息可以：
1. 自动生成 CHANGELOG
2. 快速定位代码变更
3. 便于代码审查
4. 支持自动化版本管理
5. 提高团队协作效率
