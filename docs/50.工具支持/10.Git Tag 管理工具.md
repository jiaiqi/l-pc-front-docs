# Git Tag 管理工具

> **交互式 Git Tag 创建与管理工具，简化版本发布流程**

本文档介绍项目中使用的 Git Tag 管理工具，帮助开发者更方便地创建、推送和管理 Git 标签，实现版本发布的自动化。

## 功能特性

- **交互式命令行界面**：友好的交互体验，引导式操作流程
- **自动检测当前分支**：智能识别当前工作分支
- **未提交更改检测**：自动检查并提示未提交的更改
- **智能版本号建议**：基于最新标签自动生成下一个版本号
- **语义化版本验证**：验证版本号格式是否符合语义化版本规范
- **提交记录集成**：自动获取并格式化自上次发布以来的提交记录
- **编辑器集成**：支持在编辑器中编辑标签描述
- **一键创建与推送**：简化标签创建和远程推送流程
- **可选生成版本文件**：支持自动生成项目版本文件
- **可选构建项目**：支持标签创建后自动构建项目
- **跨平台支持**：兼容 Windows、macOS、Linux 系统

## 前置条件

在使用本工具前，请确保已安装以下依赖：

- **Node.js** >= 18.20.8
- **Git** >= 2.0

## 使用方法

### 启动工具

在项目根目录下运行以下命令启动工具：

```bash
npm run git-tag
```

或直接运行脚本文件：

```bash
node scripts/git-tag-cli.js
```

### 操作流程

#### 1. 分支检测

工具启动后会自动检测当前分支并显示：

```
🚀 Git Tag 提交工具
==================
当前分支: main
```

#### 2. 未提交更改检查

工具会自动检查是否存在未提交的更改：

- 如果存在未提交的更改，会显示警告并询问是否继续
- 建议选择提交或暂存更改后再继续操作

```
⚠️  警告: 存在未提交的更改，请先提交或暂存更改
是否继续? 输入 y 则忽略未提交的更改，否则会退出流程 (y/N)
```

#### 3. 版本号建议

工具会自动获取最新的 Git Tag，并建议下一个版本号：

```
建议版本号: v1.2.4
```

**版本号生成规则：**
- 解析最新标签（如 `v1.2.3`）
- 自动递增补丁版本号（如 `v1.2.4`）
- 如果没有历史标签，默认建议 `v1.0.0`

#### 4. 提交记录查看

工具会自动获取自上次发布以来的提交记录：

```
📋 自上次发布以来的提交记录:
2025-01-30 10:00 【abc1234】
feat: 添加用户登录功能

文件:
src/components/Login.vue
src/api/user.js
===========================
2025-01-29 15:30 【def5678】
fix: 修复表格排序问题

文件:
src/components/Table.vue
```

#### 5. 标签描述设置

可以选择使用提交记录作为标签描述，或在编辑器中编辑，或输入自定义描述：

```
是否使用上述提交记录作为标签描述? (Y/n/e:编辑)
```

**选项说明：**

| 选项 | 说明 |
|------|------|
| `Y` 或回车 | 直接使用提交记录作为标签描述 |
| `n` | 输入自定义标签描述 |
| `e` | 在编辑器中编辑提交记录 |

**使用提交记录（Y）：**

```
✅ 已选择使用提交记录作为标签描述:
```

**在编辑器中编辑（e）：**

```
📝 将在编辑器中编辑标签描述...
已生成临时文件，请在编辑器中编辑...
临时文件路径: E:\project\.git-tag-tmp-1234567890.txt
使用 VSCode 打开文件...
```

支持的编辑器：Notepad++、VSCode、记事本（Windows）、Nano、Vim（Linux/Mac）

**自定义描述（n）：**

```
请输入自定义标签描述 (必填)
```

#### 6. 版本号输入

输入版本号（可使用建议的默认值）：

```
请输入版本号 (必填) (默认: v1.2.4)
```

**版本号规范：**
- 支持格式：`v1.2.3` 或 `1.2.3`
- 会自动添加 `v` 前缀（如果未提供）
- 必须符合语义化版本规范（SemVer）

**语义化版本格式：**

```
v主版本号.次版本号.修订版本号-预发布版本+构建元数据
```

示例：
- `v1.0.0` - 正式版本
- `v1.2.3-beta.1` - 预发布版本
- `v2.0.0+build.123` - 带构建元数据

#### 7. 操作确认

显示操作摘要，确认后执行：

```
📋 操作确认
版本号: v1.2.4
标签描述: feat: 添加用户登录功能...
当前分支: main
是否确认创建并推送标签? (y/N)
```

#### 8. 创建与推送标签

确认后，工具将自动执行以下操作：

```
📦 创建本地标签...
✅ 本地标签 v1.2.4 创建成功

📤 推送标签到远程...
✅ 标签 v1.2.4 推送成功
```

#### 9. 可选操作

##### 生成版本文件

```
是否生成版本文件? (y/N)
```

选择 `y` 将执行 `npm run generate-version`，生成 `public/version.json` 文件。

##### 构建项目

```
是否构建项目? (y/N)
```

选择 `y` 将执行 `npm run build:version`，构建生产版本。

#### 10. 完成

```
🎉 标签提交完成!

```

## 核心功能实现

### 版本号验证

工具使用正则表达式验证语义化版本格式：

```javascript
const validateSemanticVersion = (version) => {
  const semanticRegex = /^v?(\d+)(\.(\d+))?(\.(\d+))?(?:-([0-9A-Za-z-]+(?:\.[0-9A-Za-z-]+)*))?(?:\+([0-9A-Za-z-]+(?:\.[0-9A-Za-z-]+)*))?$/;
  return semanticRegex.test(version);
};
```

### 智能版本号建议

```javascript
const getNextVersion = () => {
  try {
    // 获取最近的 tag
    const latestTag = execSync('git describe --tags --abbrev=0', { stdio: 'pipe' }).toString().trim();

    // 解析版本号
    const match = latestTag.match(/v?(\d+)\.(\d+)\.(\d+)/);
    if (match) {
      const [, major, minor, patch] = match;
      return `v${major}.${minor}.${parseInt(patch) + 1}`;
    }
    return 'v1.0.0';
  } catch (error) {
    // 如果没有 tag，默认使用 v1.0.0
    return 'v1.0.0';
  }
};
```

### 提交记录获取

```javascript
const getCommitLogsSinceLastTag = () => {
  try {
    // 获取最近的 tag
    const latestTag = execSync('git describe --tags --abbrev=0', { stdio: 'pipe' }).toString().trim();

    // 获取自上次 tag 以来的提交日志，包含影响的文件，忽略 merge 提交
    const commitLogs = execSync(
      `git log ${latestTag}..HEAD --pretty=format:"%ad 【%h】%n%s%n%b%n文件: " --date=format:"%Y-%m-%d %H:%M" --name-only --reverse --no-merges`,
      { stdio: 'pipe' }
    ).toString().trim();

    if (commitLogs) {
      // 在每个提交之间添加分隔符
      const lines = commitLogs.split('\n');
      const formattedLogs = [];
      
      for (let i = 0; i < lines.length; i++) {
        // 检测到新的提交开始（日期行）且不是第一个提交
        if (lines[i].match(/^\d{4}-\d{2}-\d{2} \d{2}:\d{2}/) && i > 0) {
          formattedLogs.push('===========================');
        }
        formattedLogs.push(lines[i]);
      }
      
      return formattedLogs.join('\n');
    }
    return '暂无提交记录';
  } catch (error) {
    // 如果没有 tag 或获取失败，返回最近 10 次提交日志
    try {
      const recentLogs = execSync(
        'git log -10 --pretty=format:"%ad 【%h】%n%s%n%b%n文件: " --date=format:"%Y-%m-%d %H:%M" --name-only --reverse --no-merges',
        { stdio: 'pipe' }
      ).toString().trim();

      if (recentLogs) {
        const lines = recentLogs.split('\n');
        const formattedLogs = [];
        
        for (let i = 0; i < lines.length; i++) {
          if (lines[i].match(/^\d{4}-\d{2}-\d{2} \d{2}:\d{2}/) && i > 0) {
            formattedLogs.push('===========================');
          }
          formattedLogs.push(lines[i]);
        }
        
        return formattedLogs.join('\n');
      }
    } catch (recentError) {
      return '无法获取提交记录';
    }
    return '暂无提交记录';
  }
};
```

### 编辑器集成

工具支持多种编辑器编辑标签描述：

```javascript
const editDescriptionWithEditor = async (defaultDescription) => {
  const tmpFile = path.resolve(process.cwd(), `.git-tag-tmp-${Date.now()}.txt`);
  fs.writeFileSync(tmpFile, defaultDescription, 'utf8');

  // 检测所有可用的编辑器
  const detectAvailableEditors = () => {
    const editors = [];

    // Windows 环境下检测
    if (process.platform === 'win32') {
      // 1. 检测 Notepad++
      try {
        execSync('where notepad++', { stdio: 'pipe' });
        editors.push({ cmd: 'notepad++', name: 'Notepad++', args: '-nosession -notabbar' });
      } catch (e) {
        // 检查常见安装路径
        const commonPaths = [
          'C:\\Program Files\\Notepad++\\notepad++.exe',
          'C:\\Program Files (x86)\\Notepad++\\notepad++.exe',
          `${process.env.LOCALAPPDATA}\\Programs\\Notepad++\\notepad++.exe`
        ];
        for (const npPath of commonPaths) {
          if (fs.existsSync(npPath)) {
            editors.push({ cmd: `"${npPath}"`, name: 'Notepad++', args: '-nosession -notabbar' });
            break;
          }
        }
      }

      // 2. 检测 VSCode
      try {
        execSync('where code', { stdio: 'pipe' });
        editors.push({ cmd: 'code', name: 'VSCode', args: '--wait' });
      } catch (e) {}

      // 3. 记事本（始终可用）
      editors.push({ cmd: 'notepad', name: '记事本', args: '' });
    } else {
      // Linux/Mac 环境
      try {
        execSync('which nano', { stdio: 'pipe' });
        editors.push({ cmd: 'nano', name: 'Nano', args: '' });
      } catch (e) {}

      try {
        execSync('which vim', { stdio: 'pipe' });
        editors.push({ cmd: 'vim', name: 'Vim', args: '' });
      } catch (e) {}

      try {
        execSync('which code', { stdio: 'pipe' });
        editors.push({ cmd: 'code', name: 'VSCode', args: '--wait' });
      } catch (e) {}
    }

    return editors;
  };
```

## 最佳实践

### 1. 版本号命名规范

- **主版本号（Major）**：不兼容的 API 修改
- **次版本号（Minor）**：向下兼容的功能性新增
- **修订版本号（Patch）**：向下兼容的问题修正

示例：
- `v1.0.0` - 初始发布
- `v1.1.0` - 新增功能
- `v1.1.1` - 修复 Bug
- `v2.0.0` - 重大更新

### 2. 标签描述编写

- 清晰描述本次发布的主要内容
- 列出重要的功能变更和修复
- 参考提交记录格式：`<类型>: <描述>`

**常用类型：**
- `feat` - 新功能
- `fix` - 修复
- `docs` - 文档
- `style` - 格式
- `refactor` - 重构
- `test` - 测试
- `chore` - 构建/工具

### 3. 发布流程建议

1. 完成功能开发和测试
2. 提交所有更改到版本控制
3. 运行 `npm run git-tag` 创建标签
4. 生成版本文件（可选）
5. 构建项目（可选）
6. 验证发布结果

### 4. 标签管理

**查看所有标签：**

```bash
git tag -l
```

**查看标签详情：**

```bash
git show v1.2.4
```

**删除本地标签：**

```bash
git tag -d v1.2.4
```

**删除远程标签：**

```bash
git push origin --delete v1.2.4
```

## 常见问题

### Q: 版本号格式错误怎么办？

A: 确保版本号符合语义化版本规范，例如：
- 正确：`v1.2.3`、`1.2.3`、`v1.2.3-beta.1`
- 错误：`v1.2`、`version1.2.3`、`1.2.3.4.5`

### Q: 推送标签失败怎么办？

A: 检查以下几点：
1. 是否有远程仓库写入权限
2. 网络连接是否正常
3. 标签是否已存在于远程仓库

### Q: 如何回滚标签？

A: 如果标签推送后发现问题：

```bash
# 删除本地标签
git tag -d v1.2.4

# 删除远程标签
git push origin --delete v1.2.4

# 重新创建并推送
git tag -a v1.2.4 -m "修正后的描述"
git push origin v1.2.4
```

### Q: 可以修改已推送的标签吗？

A: **不建议修改已推送的标签**。如果必须修改，需要：
1. 删除本地和远程标签
2. 重新创建标签
3. 通知团队成员更新本地标签
