::: tip 序言

本文档定义了 l-pc-front 项目文档的编写规范，旨在统一文档风格、提高文档质量、降低维护成本。所有文档编写者都应遵循本规范。

:::

## 文档结构规范

### Frontmatter 规范

每个 Markdown 文件必须包含完整的 Frontmatter 配置：

```yaml
---
title: 文档标题
date: 2025-01-07 10:00:00
permalink: /guide/example
categories:
  - 分类名称
tags:
  - 标签1
  - 标签2
sidebar: true
sidebarSort: 10
---
```

**必填字段：**

- `title`: 文档标题，必须与文件名保持一致
- `date`: 创建或更新日期，格式为 `YYYY-MM-DD HH:mm:ss`
- `permalink`: 永久链接，使用英文路径

**可选字段：**

- `categories`: 分类列表，建议每个文档至少一个分类
- `tags`: 标签列表，建议 2-5 个相关标签
- `sidebar`: 是否显示在侧边栏，默认 `true`
- `sidebarSort`: 侧边栏排序，数值越小越靠前
- `top`: 是否置顶到首页，默认 `false`

### 文档标题规范

**一级标题（H1）：**

- 每个文档必须有且仅有一个一级标题
- 一级标题应与 Frontmatter 中的 `title` 保持一致
- 使用 `#` 符号标记

```markdown
# 文档标题
```

**二级标题（H2）：**

- 用于文档的主要章节
- 使用 `##` 符号标记
- 建议每个文档至少包含 3-5 个二级标题

```markdown
## 章节标题
```

**三级标题（H3）：**

- 用于章节的子内容
- 使用 `###` 符号标记
- 不建议超过三级标题

```markdown
### 小节标题
```

### 文档开头规范

每个文档应在一级标题后添加简要描述：

```markdown
# 文档标题

> 文档简介或描述，简要说明本文档的内容和目的。

## 章节标题
```

## 内容编写规范

### 段落规范

- 每个段落之间空一行
- 段落开头不缩进
- 段落长度适中，建议不超过 200 字

**正确示例：**

```markdown
这是第一段内容。

这是第二段内容。
```

**错误示例：**

```markdown
这是第一段内容。
这是第二段内容，没有空行。
```

### 列表规范

**无序列表：**

- 使用 `-` 作为列表标记
- 列表项之间不空行
- 列表项末尾不加标点符号

```markdown
- 列表项 1
- 列表项 2
- 列表项 3
```

**有序列表：**

- 使用 `1.`、`2.`、`3.` 作为列表标记
- 列表项之间不空行
- 列表项末尾不加标点符号

```markdown
1. 第一步
2. 第二步
3. 第三步
```

**嵌套列表：**

- 使用缩进表示嵌套层级
- 每级缩进 2 个空格

```markdown
- 一级列表项
  - 二级列表项
    - 三级列表项
- 另一个一级列表项
```

### 代码块规范

**代码块标记：**

- 使用三个反引号 `` ``` `` 包裹代码
- 指定语言类型，如 `javascript`、`bash`、`python` 等
- 代码块前后空一行

```markdown
```javascript
function example() {
  console.log('Hello World');
}
```
```

**行内代码：**

- 使用单个反引号 `` ` `` 包裹代码
- 代码与前后文字之间加空格

```markdown
在 JavaScript 中，使用 `console.log()` 输出信息。
```

**代码块标题：**

- 可以为代码块添加标题说明

```markdown
```javascript title: 示例代码
function example() {
  console.log('Hello World');
}
```
```

### 链接规范

**内部链接：**

- 使用相对路径
- 链接文字前后加空格

```markdown
请参考 [项目概览](/overview/overview) 了解更多信息。
```

**外部链接：**

- 使用完整的 URL
- 链接文字前后加空格
- 建议添加 `target="_blank"` 属性

```markdown
访问 [VitePress 官方文档](https://vitepress.dev/) 了解更多信息。
```

**链接文字规范：**

- 链接文字应简洁明了
- 避免使用"点击这里"、"查看"等模糊文字

**正确示例：**

```markdown
请参考 [VitePress 文档](https://vitepress.dev/) 了解更多信息。
```

**错误示例：**

```markdown
请 [点击这里](https://vitepress.dev/) 查看文档。
```

### 图片规范

**图片引用：**

- 使用相对路径，以 `/` 开头
- 图片路径指向 `docs/public/` 目录
- 必须添加 `alt` 属性描述图片内容

```markdown
![图片描述](/image/example.png)
```

**图片尺寸：**

- 图片宽度建议不超过 800px
- 大图片建议使用缩略图
- 可以指定图片尺寸

```markdown
![图片描述](/image/example.png =600x400)
```

**图片对齐：**

- 默认左对齐
- 可使用 HTML 标签居中对齐

```markdown
<div align="center">
  <img src="/image/example.png" alt="图片描述" width="600">
  <p>图片说明</p>
</div>
```

### 表格规范

**表格格式：**

- 使用 Markdown 表格语法
- 表头和内容之间用 `|` 分隔
- 表格前后空一行

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 内容1 | 内容2 | 内容3 |
| 内容4 | 内容5 | 内容6 |
```

**表格对齐：**

- 默认左对齐
- 可指定对齐方式：`:-` 左对齐、`:-:` 居中、`-:` 右对齐

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|------:|
| 内容1  | 内容2 | 内容3 |
```

**表格规范：**

- 表格应有清晰的标题
- 列名应简洁明了
- 避免表格过宽，建议不超过 6 列

### 引用规范

**普通引用：**

- 使用 `>` 符号标记
- 引用内容前后空一行

```markdown
> 这是一段引用内容。
> 可以包含多行。
```

**嵌套引用：**

- 使用多个 `>` 符号表示嵌套层级

```markdown
> 第一层引用
>
> > 第二层引用
```

**引用规范：**

- 引用应注明来源
- 引用内容应准确无误
- 避免大段引用

### 提示框规范

**提示框类型：**

- `tip`: 提示信息
- `warning`: 警告信息
- `danger`: 危险信息
- `info`: 信息提示

**提示框格式：**

```markdown
::: tip 提示
这是一个提示信息。
:::

::: warning 警告
这是一个警告信息。
:::

::: danger 危险
这是一个危险信息。
:::

::: info 信息
这是一个信息提示。
:::
```

**提示框使用规范：**

- 提示框标题应简洁
- 提示框内容应简洁明了
- 避免过度使用提示框

### 分隔线规范

**分隔线格式：**

- 使用三个或更多 `-` 或 `*` 符号
- 分隔线前后空一行

```markdown
---

这是分隔线后的内容。
```

**分隔线使用规范：**

- 用于分隔主要内容
- 避免过度使用分隔线
- 建议每个文档不超过 3 个分隔线

## 文档命名规范

### 文件名规范

**博客风格（推荐）：**

- 使用序号前缀：`01.文件名.md`、`02.文件名.md`
- 序号决定在侧边栏中的显示顺序
- 建议使用间隔序号：`10、20、30`

```
docs/
├─ 01.指南/
│  ├─ 01.简介/
│  │  ├─ 01.项目概览.md
│  │  └─ 05.快速开始.md
```

**文档风格：**

- 使用英文文件名
- 文件名作为 URL 路径
- 使用 `sidebarSort` 配置排序

```
docs/
├─ guide/
│  ├─ overview.md
│  └─ quickstart.md
```

### 目录名规范

- 使用序号前缀：`01.目录名`
- 目录名应简洁明了
- 建议使用中文目录名

```
docs/
├─ 01.指南/
├─ 02.架构设计/
├─ 03.核心功能/
```

### 文件名与标题一致性

- 文件名应与 Frontmatter 中的 `title` 保持一致
- 去除序号前缀后，文件名应与标题一致

**正确示例：**

```yaml
---
title: 快速开始
---

文件名：05.快速开始.md
```

## 文档内容规范

### 文档完整性

**每个文档应包含：**

1. 完整的 Frontmatter 配置
2. 一级标题
3. 文档简介
4. 主要章节（至少 3 个二级标题）
5. 相关链接或参考文档

### 文档质量

**内容要求：**

- 内容准确无误
- 逻辑清晰明了
- 语言简洁易懂
- 示例代码可运行

**更新要求：**

- 及时更新过时内容
- 标注最后更新日期
- 记录重要变更

### 文档长度

- 建议每个文档 500-2000 字
- 过长文档应拆分为多个文档
- 过短文档应合并或补充内容

## 代码示例规范

### 代码完整性

**每个代码示例应包含：**

1. 完整的代码片段
2. 代码注释说明
3. 运行结果或预期输出
4. 适用场景说明

```markdown
### 示例：创建 Vue 组件

```javascript
// 创建一个简单的 Vue 组件
const MyComponent = {
  template: '<div>Hello World</div>'
};

// 注册组件
Vue.component('my-component', MyComponent);
```

**运行结果：**

```
Hello World
```

**适用场景：** 简单的静态组件展示
```

### 代码注释

- 关键代码必须添加注释
- 注释应简洁明了
- 注释使用中文

```javascript
// 创建 Vue 实例
const app = new Vue({
  el: '#app',
  data: {
    message: 'Hello World' // 初始消息
  }
});
```

### 代码格式化

- 使用统一的代码格式
- 遵循语言规范
- 使用 2 个空格缩进

```javascript
// 正确格式
function example() {
  if (condition) {
    doSomething();
  }
}

// 错误格式
function example(){
  if(condition){
    doSomething();
  }
}
```

## 文档审查规范

### 自查清单

**发布文档前，请检查以下内容：**

- [ ] Frontmatter 配置完整
- [ ] 标题层级正确
- [ ] 链接可正常访问
- [ ] 图片可正常显示
- [ ] 代码示例可运行
- [ ] 拼写和语法正确
- [ ] 格式符合规范
- [ ] 内容准确无误

### 同行评审

- 重要文档应进行同行评审
- 评审者应检查文档质量和准确性
- 根据评审意见修改文档

## 文档维护规范

### 版本控制

- 使用 Git 进行版本控制
- 提交信息应清晰明了
- 重要变更应添加说明

```bash
git add docs/01.指南/01.简介/01.项目概览.md
git commit -m "docs: 更新项目概览文档"
```

### 文档更新

- 定期检查文档的时效性
- 及时更新过时内容
- 记录更新历史

### 文档归档

- 过时文档应归档或删除
- 归档文档应标记为过时
- 删除文档应谨慎操作

## 特殊文档规范

### API 文档规范

**API 文档应包含：**

1. API 简介
2. 请求方法
3. 请求参数
4. 响应参数
5. 示例代码
6. 错误码说明

```markdown
## 用户登录 API

### 请求信息

- **接口地址：** `/api/login`
- **请求方法：** `POST`
- **Content-Type：** `application/json`

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

### 请求示例

```javascript
fetch('/api/login', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    username: 'admin',
    password: '123456'
  })
});
```

### 响应参数

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | number | 状态码 |
| message | string | 提示信息 |
| data | object | 返回数据 |

### 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 401 | 未授权 |
| 404 | 未找到 |
| 500 | 服务器错误 |
```

### 教程文档规范

**教程文档应包含：**

1. 教程简介
2. 前置条件
3. 步骤说明
4. 示例代码
5. 常见问题
6. 参考资源

```markdown
## Vue 组件开发教程

### 教程简介

本教程将教你如何开发一个 Vue 组件。

### 前置条件

- Node.js >= 18.20.8
- Vue >= 2.7.0
- 基础 JavaScript 知识

### 步骤说明

#### 步骤 1：创建组件文件

```javascript
// MyComponent.js
export default {
  name: 'MyComponent',
  template: '<div>Hello World</div>'
};
```

#### 步骤 2：注册组件

```javascript
import MyComponent from './MyComponent.js';

Vue.component('my-component', MyComponent);
```

#### 步骤 3：使用组件

```html
<my-component></my-component>
```

### 常见问题

**Q: 组件无法渲染？**

A: 检查组件是否正确注册。

### 参考资源

- [Vue 官方文档](https://vuejs.org/)
- [组件开发指南](/guide/component)
```

## 常见错误示例

### Frontmatter 错误

**错误示例：**

```yaml
---
title: 文档标题
# 缺少 date 字段
# 缺少 permalink 字段
---
```

**正确示例：**

```yaml
---
title: 文档标题
date: 2025-01-07 10:00:00
permalink: /guide/example
---
```

### 标题错误

**错误示例：**

```markdown
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
# 标题层级过多
```

**正确示例：**

```markdown
## 二级标题
### 三级标题
```

### 链接错误

**错误示例：**

```markdown
请[点击这里](/guide/example)查看文档。
```

**正确示例：**

```markdown
请参考 [文档示例](/guide/example) 了解更多信息。
```

### 代码块错误

**错误示例：**

```markdown
```javascript
function example() {
  console.log('Hello World');
}
```
没有指定语言类型
```

**正确示例：**

```markdown
```javascript
function example() {
  console.log('Hello World');
}
```
```
